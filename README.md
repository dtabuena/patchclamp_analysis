## Overview

`patchclamp_analysis` is an installable Python package for automated analysis of whole-cell patch-clamp recordings. Starting from raw Axon Binary Format (.abf) files, the pipeline runs protocol-specific analyzers across a dataset of recordings, stores results in a structured HDF5 database, reorganizes data by cell, and exports a summary Excel workbook ready for graphing in Prism.

The package is designed for multi-protocol datasets in which each cell may have several recordings (resting membrane potential, membrane test, rheobase, firing gain, input resistance, spike latency, and voltage-clamp I-V curves). A single notebook drives the full analysis from raw files to a per-cell HDF5 and a per-genotype Excel export.

## Inputs

### ABF Recordings

Axon Binary Format files (`.abf`) are the raw electrophysiology recordings produced by Axon instruments (pClamp/Clampex). The pipeline finds all `.abf` files recursively under the folder you specify, so you do not need to move or rename files as long as they are somewhere inside the data directory.

#### Filename Convention

ABF files must be named with underscore-delimited fields matching the entries in `file_naming_scheme`. The default scheme used in the testing notebook expects eight fields:

```
<rec_date>_<genotype>_<sex>_<age>_<orientation>_<slice>_<cell_num>_<cell_type>.abf
```

| Field | Example | Notes |
|---|---|---|
| rec_date | 2025x02x28 | Use `x` as separator (not dashes, which break parsing) |
| genotype | MAPT | Free text; must be consistent across cells |
| sex | F | F or M |
| age | P275 | Postnatal days; prefix P |
| orientation | sagi | sagi or coronal |
| slice | s002 | Prefix s; zero-padded |
| cell_num | c001 | Prefix c; zero-padded |
| cell_type | SST | Cell type label (e.g. SST, PV, DLX) |

The `file_naming_scheme` list in `dataset_info` must have exactly as many entries as there are underscore-delimited tokens in your filenames. The pipeline generates a `cell_id` field by joining the first N-1 tokens, which is used later to group recordings by cell.

#### Supported Protocols

The pipeline matches ABF files to analyzer functions by the protocol name stored in the ABF header. The protocol name in the file must match the key in `analyzer_configs` exactly (case-sensitive). The default configuration in `analysis_parameters.init_func_arg_dicts_h5()` recognizes the following protocols:

| Protocol name (ABF header) | Analyzer | What it measures |
|---|---|---|
| `VC - 3min GapFree` | `rmp_analyzer` | Resting membrane potential from a gap-free voltage-clamp recording |
| `I0 - 3min GapFree` | `rmp_analyzer` | Resting membrane potential from a gap-free current-clamp recording at I=0 |
| `IC - Rheobase` | `rheobase_analyzer_V2` | Rheobase current, AP threshold, and single AP waveform parameters |
| `IC - Gain - D10pA` | `gain_analyzer_v2` | Firing rate gain (Hz/pA) with 10 pA current steps |
| `IC - Gain - D20pA` | `gain_analyzer_v2` | Firing rate gain (Hz/pA) with 20 pA current steps |
| `IC - Gain - D25pA` | `gain_analyzer_v2` | Firing rate gain (Hz/pA) with 25 pA current steps |
| `IC - Gain - D50pA` | `gain_analyzer_v2` | Firing rate gain (Hz/pA) with 50 pA current steps |
| `VC - MemTest-10ms-160ms` | `membrane_analyzer` | Membrane capacitance, access resistance, and membrane resistance |
| `IC - Latentcy 800pA-1s` | `latencey_analyzer` | First spike latency from a ramp current injection |
| `IC - R input` | `input_resistance_analyzer` | Input resistance and Ih sag slope |
| `VC - Multi IV - 150ms` | `IV_analyzer_v4` | Voltage-gated Na and K current amplitudes from a 150 ms step IV protocol |
| `VC - Multi IV - 500ms` | `IV_analyzer_v4` | Voltage-gated Na and K current amplitudes from a 500 ms step IV protocol |

## Outputs

### HDF5 Files (.h5)

Two HDF5 files are produced during analysis.

| File | Contents | When created |
|---|---|---|
| `<data_name>_analysis_recs.h5` | One group per ABF recording inside an `abf_files` parent group. Each group stores the raw analysis result arrays and scalars as datasets, plus all metadata as group attributes (filepath, protocol, genotype, age, cell_id, etc.) | After `build_analysis_h5()` and `analysis_iterator_h5()` |
| `<data_name>_analysis_cells.h5` | Same data reorganized so that each top-level group is one cell (identified by `cell_id`). All recording datasets from that cell are merged into the cell group. ### Step 1 -- Prepare your files

- Organize ABF files in a data folder (subfolders are fine; the pipeline searches recursively).
- Rename ABF files if needed so that underscore-delimited tokens match your `file_naming_scheme`.
- Set `working_dir` in the notebook to the root of your data directory.

### Step 2 -- Configure the dataset and run analysis

This cell defines the dataset, discovers all ABF files, reads protocol metadata, runs all analyzers, and writes `_analysis_recs.h5`.

```python
dataset_info = {
    'data_name': 'MAPT_DLX_SST',
    'data_source': os.path.join(working_dir),
    'file_naming_scheme': ['rec_date', 'genotype', 'sex', 'age',
                           'orientation', 'slice', 'cell_num', 'cell_type'],
}

h5_data_loc = build_analysis_h5(dataset_info)
print_h5_tree(h5_data_loc, head=10)

analyzer_configs = analysis_parameters.init_func_arg_dicts_h5()
analysis_iterator_h5(h5_data_loc, analyzer_configs)
```

**What each call does:**

| Call | What happens |
|---|---|
| `build_analysis_h5(dataset_info)` | Recursively finds all `.abf` files under `data_source`, parses filenames using `file_naming_scheme`, reads the protocol name and channel list from each ABF header, and writes a `_analysis_recs.h5` file with one group per recording inside `abf_files/`. Returns the path to the new HDF5 file. |
| `print_h5_tree(h5_data_loc, head=10)` | Prints the first N lines of the HDF5 tree structure. Use this to verify files were found and parsed correctly before committing time to the full analysis. |
| `analysis_parameters.init_func_arg_dicts_h5()` | Returns the default `analyzer_configs` dict mapping protocol names to analysis functions and their keyword arguments. Edit this function or override the dict to change spike detection thresholds, IV windows, or which protocols are analyzed. |
| `analysis_iterator_h5(h5_data_loc, analyzer_configs)` | Iterates over all recording groups, looks up the appropriate analyzer by protocol name, runs it, and writes results back into the HDF5 as datasets. Returns a list of filepaths that raised exceptions during analysis. |

**What you need to edit:**

- `data_name` -- short identifier used as the stem for all output filenames
- `data_source` -- path to the root of your data directory
- `file_naming_scheme` -- list of field names with one entry per underscore-delimited token in your ABF filenames
- To adjust analysis parameters (spike thresholds, IV windows, gain step limits, etc.), edit the `analyzer_configs` dict returned by `init_func_arg_dicts_h5()` before passing it to `analysis_iterator_h5()`

## Analysis Methods

### Spike Detection

All current-clamp analyzers use a shared derivative-threshold method implemented in `find_spike_in_trace()`. An action potential is identified by three simultaneous criteria: the voltage derivative (dV/dt) must cross a rising threshold (`spike_thresh`, typically 10-15 mV/ms), must also exceed a higher confirmation threshold (`high_dv_thresh`, typically 20-30 mV/ms), and a falling phase below `low_dv_thresh` (typically -5 to -15 mV/ms) must occur within `window_ms` milliseconds of onset. A refractory period of 5 ms prevents double-counting. Stimulus periods are determined automatically from sweep-to-sweep command variance so that only spikes during the current injection are counted.

### Resting Membrane Potential

The first 3 seconds of the recording are used. The mean membrane potential is reported only if the mean holding current is below 15 pA in absolute value, ensuring the cell is truly at rest. Voltage-clamp gap-free recordings are detected automatically and routed to the same function.

### Rheobase and Action Potential Waveform

Sweeps are tested in order for the transition from zero spikes to one or more spikes. The minimum current evoking a spike is reported as rheobase. For single AP parameter extraction, the trace at the rheobase sweep is upsampled 4x by quadratic interpolation before measuring AP amplitude, half-width, rise time, fall time, fast afterhyperpolarization, and dV/dt max and min.

### Firing Rate Gain

Spike counts and rates are collected across all sweeps that fall within the specified holding potential window (`Vh_hilo`). A linear regression is fit to the sub-saturating, monotonically increasing portion of the firing rate vs. current curve (limited to `max_fit_steps` points). The slope of this fit is the gain in Hz/pA. Spike frequency inactivation is detected as the current step at which the instantaneous ISI-derived rate drops below 90% of the count-based rate. Adaptation metrics are computed from ISI series at the maximum-frequency sweep.

### Membrane Properties

Square voltage pulses are averaged across sweeps and across matching pulse durations. The capacitive transient is fit with a monoexponential using `scipy.optimize.curve_fit`, giving access resistance (Ra), membrane resistance (Rm), and the fitted time constant (tau). Capacitance is reported three ways: from charge integration under the transient (Cmq), from the time constant and resistance (Cmf), and from charge integration under the fitted curve (Cmqf). A parallel pClamp-style calculation using the linearized exponential method is also performed (Cm_pc, Ra_pc, Rm_pc).

### Input Resistance and Ih Sag

For each hyperpolarizing and small depolarizing current step, the steady-state delta-V is measured from a 100 ms window at the end of the step using a 5 Hz low-pass Butterworth filter. A linear regression across sweeps within `dVm_limits` gives input resistance. Outlier sweeps with standardized residuals above 3 are excluded and the fit is repeated. Ih sag is quantified separately as the slope of a linear fit between peak hyperpolarization and sag amplitude for all sweeps hyperpolarized below -75 mV.

### Spike Latency

A ramp current injection drives the cell to threshold. The first spike is detected using the standard derivative method. Latency is measured from ramp onset to the spike onset index. If multiple sweeps are present, the sweep with holding potential nearest to -70 mV is selected. AP threshold and rheobase current at the spike are also reported.

### Voltage-Clamp IV Curves

Sweeps with baseline currents below `leak_threshold` (default -400 pA) or with saturated traces (|I| > 1000 pA at the last sample) are excluded. P/N leak subtraction is applied by averaging normalized responses from specified hyperpolarized voltage steps (`PN_voltages`) and scaling this template to each test voltage. Baseline subtraction removes the holding current offset. Na-channel peak current is taken as the largest deviation from the median within the Na time window. K-channel current is the median within the K time window.

### Current Density

To normalize for differences in cell size, IV current amplitudes are divided by membrane capacitance (Cmq from the membrane test protocol). The result is stored as new datasets prefixed with `density_` in the cells HDF5.

### Sweep QC

`qc_sweep()` in `abf_handling` computes holding potential, leak current, and both high-frequency (first 1.5 ms pre-stimulus) and low-frequency (last 100 ms pre-stimulus) RMS noise. These values can be compared against configurable thresholds to flag sweeps for manual review.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Recording skipped: `No analyzer for protocol: <name>` | Protocol name in the ABF header does not exactly match a key in `analyzer_configs` | Check the printed protocol name against the keys in `init_func_arg_dicts_h5()`. Protocol names are case-sensitive. |
| `failed: <exception>` printed during `analysis_iterator_h5` | Analyzer raised an exception for that recording | The recording is skipped and its filepath is added to `problem_recs`. Inspect the exception message and check the file manually with `pyabf.ABF(filepath)`. |
| `<base_name> already exists, skipping` | `build_analysis_h5()` was re-run without `overwrite=True` | Pass `overwrite=True` to `build_analysis_h5()` to force re-processing, or delete the HDF5 and start fresh. |
| Dataset shows `nan` for a scalar metric | Analysis function returned `nan` (e.g., no spikes detected, fit failed, insufficient sweeps) | Check the QC figure if saved to `Saved_Figs/`; the recording may need to be excluded or re-run with adjusted parameters. |
| `No valid Sweeps` in IV results | All sweeps failed the leak threshold filter | Reduce `leak_threshold` in the IV analyzer config, or check cell quality. |
| `density_` datasets missing after `add_current_density_datasets` | `capacitance_key` not found in cell group, or capacitance is NaN or <= 0 | Confirm the membrane test was analyzed and the correct `capacitance_key` string is used (check `print_h5_tree`). |
| `flatten_nested_column` returns empty DataFrames | Dataset is scalar, not a structured array | Use `get_datasets_from_h5` and work with the DataFrame directly for scalar metrics. |
| Cells HDF5 has duplicate datasets (`_1`, `_2`) | Multiple recordings with the same protocol exist for one cell | This is expected. The pipeline keeps all alternates. Use `replace_failed_recs()` with QC criteria to select the best version. |
| `cell_id` attribute missing from groups | `file_naming_scheme` length does not match the number of tokens in filenames | Re-run `build_analysis_h5()` with the correct `file_naming_scheme`. |
